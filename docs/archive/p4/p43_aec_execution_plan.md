## 4. 第一步：播放参考观测，保持半双工

参考采用音量缩放后、已完成数字发送的 PCM；不能从网络包到达时或 `AudioService` 音量缩放前复制 TTS 原值。当前左右槽相同，只保留一份单声道参考；改变双声道策略时重新定义来源。

`submitted` 按 `i2s_channel_write()` 实际接受的完整立体声帧计数，记录部分写和超时后已接受字节；非整帧视为异常。未写出的内容不作参考，接受成功不提前标为完成。

`completed` 以 `on_sent` 为观测入口。实现前核查 IDF 中回调、自动清零及写线程的顺序，并用 stub 和设备计数验证：必须在复用／清零前对本次完成缓冲做有界值拷贝，涵盖初始空 DMA、有效音频、欠载零值及 drain 静音。若无法可靠取得本次发送值，先只保留提交／完成统计，不启用 AEC；不把未经核对的 DMA 当前值当作历史发送值。

ISR 只做计数、时间戳和固定槽拷贝，使用内部 RAM 和 ISR 允许的 API；禁止分配、PSRAM、日志、滤波、锁等待或控制器调用。工作任务再写 PSRAM 历史环。重复描述符不能重复计为应用样本；空转零值也需推进数字输出时间。

A批预算为内部RAM的8个10ms事件槽、约4KiB PCM加元数据及PSRAM的300ms／24kHz历史约14.4KiB，已有约495秒设备快照。B另有300ms／16kHz时线约11KiB、重采样状态及12帧诊断队列；约852.625秒设备日志显示internal最低39828、largest31744、分配失败0，capture／playback栈最低1176／2220字节。最大消费间隔69095µs接近80ms槽容量，本次稳定期未丢槽仍需保留负载余量；单次资源观测不能证明长期无泄漏或AEC共存。DMA保持内部内存，槽满、超窗及未知区间分别计数。

每次重建增加 `dma_generation`，先停 channel 并确认 ISR 不再引用资源再释放。旧代次事件不得进入新轮。已完成的有限旧历史可供麦克风／AFE 中尚未处理的旧回声对齐，但封闭代次不能作为新播放参考。正常结束、取消、失败、重连均有边界；identity 与 DMA 代次不混用。

SD 低、音量 0、已确认欠载零值为已知静音；没收到事件或槽溢出为未知缺口。停止放音后房间混响仍可能存在，不能认为 SD 拉低即无回声。

交付标准：音量后值和左右槽一致；部分写／尾块／drain／取消事件可解释；旧事件不污染新轮，取消后旧声音不恢复；原半双工无新增断连、AFE 停顿或首尾音问题；记录 free／min／largest、PSRAM、栈和参考队列。首步失效只停止参考观测并保留半双工，不更改上传保护阈值。

## 5. 第二步：24→16 kHz 重采样与时序对齐

B批已有191抽头2/3FIR、1979µs群延迟、64位DMA锚点、300ms参考历史、20ms数字覆盖查询及受限漂移补偿。有限相关只在播放期间采原始麦克风，等待80ms、最多每200ms分析一次，使用1600样本参考、0～80ms／1ms步长搜索。没有双讲检测，低能量／低相关／歧义／边界或参考缺失拒绝。结果仅候选附加延迟，`calibrated=0`且不调相位；用户决定跳过本轮B候选分布和主观取消补验，直接实施C。既有统计仍可用于后续诊断，不自动作为AEC的延迟校准值。

上一版B数字／资源实机通过：严格3:2、unmapped0、healthy1、完整probe约99.867%；attempt376／accepted26／rejected350却没有已通过分布，被拒720样本／相关377不能作45ms校准。新B收尾已实现4个generation／serial作用域、音量标签、保留最近通过值／min／max／81格直方图与拒绝计数，拒绝不覆盖通过值；并拆分墙钟耗时、每机会最多8块／4ms软预算、采集656字节scratch移PSRAM及锁外日志。软件／构建通过，但用户决定跳过该批硬件补验；候选分布、主观取消和新任务／资源数据仍未验收，见[记录](p43b_acoustic_statistics_acceptance.md)。进入C前的历史`d6ba892eb`运行日志的RX `overflow=11`、采集时线无效且probe attempts为0，未用于声学校准；不以旧版设备日志代替新资源水位或耗时结果。

名义比例 2／3，使用带抗混叠低通的有状态有理重采样。先评估现有库或固定系数多相 FIR 的依赖和资源。禁止每第三个样本简单丢弃，禁止逐块重置相位。480 输入名义输出 320，跨块保留滤波状态、分数相位并单列群延迟及尾部。

麦克风连续样本计数为主时线；同时观测 RX DMA／采样边界和 TX 完成，不用 Wi-Fi 到达时刻。TX 回调在一块结束时触发，反推块内时间并标记误差。RX 任务可能调度延迟，需要补 RX DMA 边界观测或校准固定缓冲量，不能把任务读取时间当采样时间。

两 I2S channel 的时钟配置、实际分频误差及长期漂移需测量，不能仅凭标称比例认定永久同步，也不未经核对断言独立晶振。记录累计 TX／RX 样本相对时间和环占用。若有慢漂移，采用平滑、有上限的重采样相位增量修正；不周期性整块丢／补，不每次取消重置麦克风全局采样编号。超出补偿范围或时间跳变则报失配，停止依赖能力并回半双工。

分别核算数字 DMA／软件缓冲、滤波和声学路径延迟。用本地已知测试声音与采集相关性取得初始范围，再规定可调延迟上下界；低相关或双讲时不盲目追踪。允许固定有界麦克风延迟缓冲，使参考已经完成可取后再 feed；不能拿尚未确认发送的未来内容作参考。300 ms 是初始历史容量，实际对齐窗口以第一步观测决定。

空闲提供有效零参考并维持采样时线；未知缺口明确报错并禁用插话，不默默补零后声称 AEC 正常。新 DMA 代次重置对应重采样状态，处理有限旧回声尾部，不重放 VAD cache。

验收：任意分块产生同一连续输出；长期 480→320 名义计数、脉冲／正弦延迟与带外抑制；尾块、静音和取消代次；模拟正负时钟偏差时相位连续、环占用有界；超窗明确失败。

## 6. 第三步：AEC 观测，暂不开自动插话

新增Kconfig `VOICE_AEC_OBSERVATION_ENABLED`，默认`n`，依赖`VOICE_LOCAL_FRONTEND_ENABLED`、`VOICE_PLAYBACK_REFERENCE_ENABLED`及`VOICE_REFERENCE_ALIGNMENT_ENABLED`。默认配置保持现有`M`路径；显式启用后使用ESP-SR的`MR`格式，并设置`aec_init=true`、`aec_mode=AEC_MODE_SR_LOW_COST`。输入按`[mic0, ref0, mic1, ref1, ...]`交错。运行时验证实际输入2通道、输出单通道、16 kHz；feed块长为每通道样本数，容量和返回约定按锁定组件版本核对，不能沿用单通道检查。每个20ms麦克风帧与参考帧必须对应同一采样坐标；在等待参考DMA完成／映射约80ms后再按原顺序feed，不得为追赶参考跳过麦克风块。

仅启用AEC，保持NS／AGC／WakeNet关闭以便对照。组件AEC模式采用`AEC_MODE_SR_LOW_COST`；记录`afe_config_check()`后的最终模式、通道、块长及实际创建结果，并建立内存／任务基线。模式切换优先受控重启；停止生产者并等feed/fetch退出后才销毁模型，不在处理中改配置。初始化失败、参考时间线无效或匹配参考缺口时，锁存错误并停止AEC依赖处理；未知参考不得以零填充冒充有效静音。已确认的播放静音可以用零参考。显式手动输入仍保留，不静默换源；播放期不自动开启云端回合或取消回复。

控制器继续阻止播报期间开启云轮。先统计 AEC 输出 VAD／电平，不自动取消回复。分别做仅播放、仅近端、双讲和刚停播测试；回声能量降低不等于双讲保真，整段 RMS 比值不能直接宣称 ERLE，只有已对齐且具备基准的远端单讲段才计算相关指标。

实机检查见[C阶段验收说明](p43c_aec_observation.md)：在参考健康且连续的条件下做远端单讲、近端单讲、双讲和刚停播测试，并记录资源。B阶段的DMA溢出专项不作为C软件实施的前置工作；若设备上仍出现溢出／参考缺口，则该轮AEC硬件效果判为不可评估，不能把零参考下的行为计作AEC通过。英文质量和风扇专项仍独立保留。

## 7. 第四步：独立启用自动插话

插话独立显式启用，依赖参考连续、AEC ready、连接及资源预算。`a` 保持半双工并关闭 D1／D2，`b` 只观察并关闭 D2，`i` 才开启自动监听和实际插话；`r/m/c/n` 关闭 D2。用户已接受当前 D1 效果并选择推进 D2，偶发误确认继续单独跟踪。

### D1：候选观察，先保留播报

D1 代码、主机检查和独立固件已交付并由用户运行，随后完成普通状态锁争用修复；软件历史报告及实机证据见[D1 实施与验收](p43d1_barge_in_observation.md)。`VOICE_BARGE_IN_OBSERVATION_ENABLED` 默认关闭，独立输出为 `build/barge-in-test/`，运行时 `b` 只观察，确认后继续播报。最新 D2 编译后 D1 仍可单独使用，固件身份以本批[D2 交接说明](p43d2_barge_in_handoff.md)为准，不把初版 `9852804f87` 当作当前固件。

D1 只在真实播放期间使用 AEC 输出建立候选，连续确认初始 200 ms，固定 PSRAM 环保留 400 ms 预录和 2 秒有界缓存。D2 共用的逐帧存储新增人声标记，当前 134 帧 × 656 bytes = 87,904 bytes；原 D1 报告中的 86,832 bytes 是历史布局。D1 短候选拒绝、超时／采样不连续保护及静音后重新观察行为保留，缓存不交接云端。

D1 硬件观察已取得：争锁不可用未再出现、真人双讲能确认；仅播报有正常区间，也仍有来源未标记的确认。用户不再追加 D1 对照并明确推进 D2，该选择允许实施下一步，不代表无人讲话误确认或全部声学指标已通过。

### D2：确认后自动停播与新轮

D2 由 `VOICE_BARGE_IN_ENABLED` 单独编译，默认关闭，依赖 D1、AEC 和自动监听。独立输出 `build/barge-in-d2/` 使用 `build/barge-in-d2-sdkconfig`；四种配置的构建身份和本批检查结果以[D2 交接说明](p43d2_barge_in_handoff.md)为准。

确认后的顺序：

1. AFE 回调只保留连续 PCM 和有界状态。控制任务核对原回复身份及修订号，将 400 ms 预录、确认期和已到达尾部一次性交给自动发言缓存；不重新等待普通自动监听的 300 ms 静音门。
2. 控制任务封存旧 epoch／turn／generation，拒绝迟到文字和声音，先执行本地停播栅栏并清软件队列，不等待网络 ACK。复用既有健康 AEC 停播路径，保留参考时间线；函数返回耗时不代表声学尾音已完全消失。
3. 发送 `response.cancel`，只接受旧回复完整身份匹配的 `response.cancelled`。收到确认后才创建新回合并发 `speech.start`；重复／其他身份 ACK 不开启新轮。协议保持原样；首次设备复测两次取消超时后，新增[服务端取消抢占与耗时诊断修复](p43d2_cancel_timeout_fix.md)，需重启服务复测。
4. 从人声确认到取消 ACK 和新上行流开启共用 2 秒预算，不为各阶段分别延长；超时、AEC 故障或缓存异常封轮并丢弃旧 PCM，不把过期缓存补传到下一轮。
5. 新轮按现有 20 ms 节拍上传，保留连续的讲话开头和 700 ms 静音尾部，一段讲话只创建一个新轮。显式 `r/m/c/n` 退出 D2，`a` 回半双工，`b` 回仅观察。

D2 设备验收仍需检查实际停声、插话识别首尾、旧声不恢复、连续多轮及非主动讲话误触发。分别记录候选／确认、本地栅栏、取消 ACK、新轮 start 和首个上行帧；本批不调整 AEC 算法、增益、模型或 750 ms 服务端媒体保护。
