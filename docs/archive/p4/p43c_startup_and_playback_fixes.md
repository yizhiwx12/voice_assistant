启动失败与播放切换失败是两条路径。原启动流程在采集任务读取之前启用 RX，初始化和 UART 输出会占用有限 DMA 队列余量；本批消除这一窗口。播放切换则重建 TX 并更换 serial，使参考 FIR 重新预热、时间映射和 SD 边界出现未知区间，持续运行的麦克风帧因此配对不全。

日志没有分配失败证据，不能将这两类错误解释为 PSRAM 不够。部分日志的 Saved PC 指向 brownout 处理函数，供电复位单独保留；不能把这些 AEC 首因全归为供电或网络，也不关闭欠压保护。本批先修复可确认的生命周期窗口，未额外改变 CPU 绑核、Wi-Fi 或网络保护预算。

## 本批实现

1. **消费者就绪后启动 RX。** 麦克风先配置、保持 disabled；完成 AFE/model 初始化和任务创建后，由采集任务调用 `startCapture()` 并立即读取。启用与首次读取之间没有 UART、模型初始化或内存分配。启动握手失败、超时和资源释放均有检查；驱动其他用户仍可采用默认立即启动方式。
2. **健康 AEC 保留 TX 时间线。** 正常播完或取消时先封存旧播放、清软件队列，再用 5 个 10 ms 零块排空 DMA，随后关闭功放；下一回复沿用 TX generation。每次零块写入之间服务参考配对，避免排空时饿死消费者。默认非 AEC 路径继续采用静音并重建 TX 的栅栏。
3. **serial 只标识播放作用域。** 同一物理 generation 的连续样本不因 serial 变化重置 FIR 或映射；通用 AEC 查询允许连接相邻有效样本，限定 serial 的声学查询仍隔离作用域。新空 DMA 或成功排空后允许多次空回复取消／重绑；任何写入撤销资格，只有成功 drain 才恢复。
4. **只认可可证明的静音。** ISR 检查原始左右 DMA 均为零且一致时，跨 SD 边界的块才可作为有效静音。非零边界、真实丢帧、部分写、错误、RX 溢出和超龄仍明确失败，不用零参考掩盖。首次有效内容前留出一个 DMA 块的稳定窗口。
5. **增加启动诊断。** `?` 快照和首次 AEC 失效日志输出 `capture_startup`，记录 enable、首次 read、首次 overflow 时间及样本边界；ISR 只锁存数据，不打印日志。启动时间用于诊断，不替代物理 DMA 对齐锚点。头文件显式包含配置，避免 AEC 初始状态依赖其他头的包含顺序。

AEC 模式取消保留最多约 **50 ms 已提交 DMA 尾音**，还需实测停声和后续恢复；已经封存的旧包不得重新播放。排空失败则明确停止 AEC 并执行硬件静音／重建保护。该模式目前仅供 C 观测，不能据此宣称已完成 D 插话的停播体验。

上次主机测试只覆盖“enable后立即调用read”，没有覆盖首次read何时返回、随后持续读取是否被调度或回调阻塞。因此它通过不能证明启动故障已解决。代码未找到可确定的控制器锁死；I2S驱动正确合并队列唤醒标志，用户回调返回false不是漏唤醒的证据。普通任务未指定核心不代表始终可迁移：IDF的float／PIE调用链可能自动固定任务，但当前没有现场实际核心记录，不能直接断言采集已固定CPU0。

另发现配对调度缺陷：`pollAecReference()`在`reference_history_pending_`为真时阻断所有待配对帧；该标志仅代表最新TX尾部仍未转换，并不代表目标旧麦克风帧的参考不完整。连续播放时，这可能让已具备完整参考的旧帧持续等待，最终超过200ms。现有`pendingHistoryDoesNotConsumeMicrophone()`把这种全局阻断写成预期，未覆盖“目标完整、较新尾部仍pending”的场景。现场缺少失效瞬间pending／最老帧信息，故不能宣称它是本次`pair_age`的唯一来源。
