## 起点与本批范围

C 阶段已得到用户反馈：仅助手播报时屏幕均为静音，同时讲话时转为人声，说完恢复静音；近端识别首尾和播完／取消后下一轮正常。记录见 [C 屏幕观察](p43c_playback_observation_ui.md)。这是基本运行和屏幕观察通过，未将双讲词句保真、定量抑制、标定或长期资源改记为通过。`calibrated=0`，B 已跳过项继续保留，无需重做此前的 14 分钟数字测试。

D1 在已有 AEC 输出上识别“短暂候选”和“持续人声已确认”，提供屏幕状态与有界统计。观察不能单独证明上传后能完整转写，也不等于已经实现插话。

## 开关与工作边界

| 项目 | 本批约定 |
| --- | --- |
| 编译开关 | `CONFIG_VOICE_BARGE_IN_OBSERVATION_ENABLED`，默认关闭，依赖 `VOICE_AEC_OBSERVATION_ENABLED` 和 `VOICE_AUTO_LISTEN_ENABLED` |
| 运行开关 | 串口 `b` 独立切换观察，开机关闭；无需先按 `a` |
| 开启条件 | 会话与 AEC 就绪，且当前录音采集已空闲；准备录音／录音／收尾期间按 `b` 会拒绝开启 |
| `a` 的含义 | 仍为既有半双工自动监听，播报中不创建新云轮 |
| `r`／`m`／`c`／`n` | 显式关闭候选观察，分别保留原手动录音、手动模式、取消、重连行为 |
| 观察区间 | 只在真实播放活动期间接收 AEC 处理后的连续 20 ms PCM；播报前／播完不补收旧音频 |
| 确认窗 | `CONFIG_VOICE_BARGE_IN_CONFIRM_MS`，初始 200 ms，可配 100～600 ms，按整 20 ms 帧取整 |
| 预录与保留预算 | 400 ms 预录，复用自动预录配置；确认后最多保留约 2 秒，复用自动握手预算 |
| 内存 | 调用者提供固定容量 PSRAM 环；原 D1 布局为 134 帧 × 648 bytes = 86,832 bytes；D2 共用布局新增人声标记后为 134 × 656 = 87,904 bytes，覆盖预录、确认、保留预算及 4 帧余量；不持续保存录音 |
| 失效处理 | AEC 不可用、采样不连续、候选缓存溢出、活动观察中超过 500 ms 无有效前端输出时，清除缓存并关闭观察；普通状态锁争用不再停用观察。回复边界由独立原子修订栅栏隔离；不因此主动中断播报或关闭连接，手动基线继续保留 |

200 ms 是首次验收的起始值，需要结合音量／摆位和实际说话判断，不能视为通用最佳阈值。确认只累计连续的前端人声帧；短于确认窗的候选不计作确认，遇到静音即拒绝并返回等待人声。单次持续讲话不会反复确认；已确认的人声结束或超出保留预算后，需先观察约 300 ms 静音才能重新进入下一次候选。

观察阶段的 PCM 只在本地有界缓存中使用，不触发 `speech.start`、上行音频或 `response.cancel`。确认后超出保留预算会丢弃本次缓存，不会在播完后上传或恢复到下一轮。

## 播报时的屏幕状态

第一行保留“播报中，不自动打断”。观察开启后，第二行显示候选状态：

| 显示 | 含义 |
| --- | --- |
| 插话观察：等待人声 | 等待连续人声候选 |
| 插话观察：人声候选 | 已出现人声，尚未达到确认窗 |
| 插话观察：人声已确认 | 已达到连续人声确认窗；仍继续播报 |
| 插话观察：等待静音 | 本次观察结束或预算用尽，等待静音后再观察 |
| 插话观察：不可用 | AEC、缓存或采样时间线条件不满足 |

关闭观察时恢复 C 阶段的“本地检测：静音／人声”。回答正文和翻页继续保留，候选变化不会替换回答或创建录音状态。

已开启观察但当前未播放时，初始页／自动监听页／回复完成页显示“插话观察：等待播报”；思考页保留原有“正在思考”，另一行显示等待播报。该提示表示开关已经启用，实际候选观察仍等播放开始。

## 独立固件与验收操作

保留现有默认 `build/` 和 AEC 基线 `build/aec-test/`，两者不主动启用 D1。独立 D1 输出位于 `build/barge-in-test/`，使用自己的配置文件，启用 AEC 和 D1 支持；运行时仍须显式按 `b`。

以下命令用于需要重烧独立 D1 固件时，在 ESP-IDF 终端分两行执行：

```powershell
cd C:\esp-project\voice_assistant
idf.py -B build/barge-in-test -p COM7 -b 115200 flash monitor
```

先关闭占用 COM7 的旧监视器。不要用 `build/aec-test/` 代替 D1 输出目录；`b` 保持只观察。下方 `0ade40c341` 表为此前争锁修复批身份，当前重新构建的身份及 D2 独立固件步骤以[D2 交接说明](p43d2_barge_in_handoff.md)为准。D1／D2 均不需要改接线、换模型或新增密钥。

从风扇关闭、固定摆位和正常音量开始；仅在这些条件下通过的结果不能扩展成所有噪声环境通过。

1. 连接就绪后用手动 `r/s` 发起一轮，**等助手实际开始播报再按 `b`** 开启观察。顺序不能颠倒，`r` 会关闭已有观察，录音准备／录音／收尾期间也不能开启。要连续观察多轮，更方便的路径是连接就绪时依次按 `a`、`b`，再说话；自动发起的新轮会保留观察开关，播报前显示“插话观察：等待播报”。
2. **仅助手播报，你保持安静。** 看屏幕观察状态，播报结束后按 `?` 保存候选／确认计数。允许记录短暂候选，但不应出现持续误确认。若确认计数增加，记录当时音量和摆位，本轮不算通过。
3. **播报中说一句完整短句。** 应看到候选转为确认，讲话持续至少超过确认窗；说完恢复等待／冷却状态。助手继续播报属于本阶段预期，所说内容不会上传识别。
4. **等候静音后再说一句。** 确认每段新的讲话只增加一次确认，持续说话不会不断重复确认。长时间讲话超过缓存保留预算时应明确丢弃该候选，不拖累播放。
5. **低一些和高一些的平常播放音量重复第 2、3 项。** 当前没有串口调音量命令，使用独立 D1 构建的 `menuconfig` 调整 `VOICE_PLAYBACK_VOLUME` 后重新构建／烧录，保留正常音量配置以便回退。记录具体音量和结果，避免仅用正常音量下的人声判定作为 D2 全量开启依据。
6. **按 `c`，或播完后开始下一轮。** 旧候选不会补传，正常手动／半双工功能及播放流畅度应保持正常。`m/r/n` 后若需继续观察，重新按 `b`。

屏幕可能来不及显示短于刷新间隔的候选，因此同时以 `?` 的累计计数与状态日志判断；不要把没看见候选瞬间直接当作没有处理。请提供测试结果、是否卡顿，以及 `?` 中的观察／本地前端／内存行。测试不要求提供密钥或整段对话内容。

## 日志怎么看

`barge_in_observation` 自动状态日志由控制任务输出，最多每秒两条，前端回调不直接打印。按 `?` 可立即获取一次快照，不受这项自动频率限制。短状态变化可能合并到后一条日志，累计计数仍保留；比较同一次测试前后的增量。

| 字段 | 含义 |
| --- | --- |
| `enabled`、`phase`、`reason` | 观察开关、当前阶段及最近边界／失效原因；等待实际播放时可能 `enabled=1 phase=disabled`，应结合 `reason` 判断 |
| `epoch`／`turn`／`generation` | 本次观察所属的旧回复身份，避免跨回复拼接候选 |
| `reply_revision`／`boundary_resets` | 当前回复修订栅栏和候选因真实回复边界清理的累计次数；加入帧前后均核对，旧事件不会交接至新轮 |
| `candidates`／`confirmations`／`rejected` | 候选数、达到连续确认窗次数、静音打断的短候选数 |
| `timeouts`／`overflows`／`discontinuities` | 确认后保留预算用尽、容量溢出、采样不连续次数 |
| `buffered`／`peak` | 当前缓存帧数和累计峰值；每帧为 20 ms |
| `candidate_sample`／`confirmed_sample` | 首个人声帧起点、达到确认窗时的样本结束位置，均使用连续 16 kHz 前端时间线 |
| `oldest_sample`／`next_sample` | 当前缓存最早样本及已接受输出的下一样本边界 |
| `upload=0 interrupt=0` | D1 只观察，不触发上传和停播 |

确认超时表示本地观察缓存按预算丢弃，不等于 ASR／云端失败。若 `reason=frontend_stalled`，表示活动观察区间中超过 500 ms 没有新的有效前端帧，本项观察将关闭；结合前端和参考健康日志分析，不把它直接归因于网络。

初版 `reason=controller_busy` 将普通锁争用误当成永久故障，本次附件已有三次，现已修复。AFE 回调及活动观察不再依赖回复状态锁；只有尚未绑定时使用非阻塞检查，锁忙推迟启用。真实回复边界用原子修订号清理，实际 AEC 故障和独立前端无进展保护仍保留。确认若与回复边界并发，累计计数可能包含一次随后已丢弃的旧事件，因此它不是声学通过证据；对照当轮 `boundary_resets` 与现场说话时刻判断。

`?` 的 `local_frontend` 行现在带 `mic_rms/mic_peak`、`ref_rms/ref_peak` 和已有的 `output_rms/output_peak`。候选或确认发生时，控制器会另记 `barge_in_energy event=candidate|confirmed`，包含时刻、AFE 输出样本位置、人声持续帧数以及三路 RMS／峰值。输入和参考能量来自最近成功入队的 20 ms 配对帧，输出能量来自最近一次 AFE fetch 块；两者不是样本精确对齐，日志明确标记 `mic_ref_output_sample_aligned=0`。播放参考是送往 AEC 的数字回放参考，不是扬声器声压测量；这些数值适合比较同机同设置下的相对变化，不足以单独证明 AEC 消除量或误触发声源。

这些能量字段通过独立原子读写取得，读快照时也不保证麦克风／参考的全部字段来自同一次配对发布。日志会重复最近一次候选／确认快照，应按 `event + epoch/turn/generation + at_us + output_sample` 去重，不能把重复打印算作多次误触发。快照保留事件发生时的回复身份；新回复启用观察时会清空旧快照。新增日志在释放采集锁后由控制任务输出，D2 的本地停播及取消发送先于本批能量日志。

### 设备对照步骤

使用当前独立 D2 固件，连接就绪、空闲时先按 `a` 开启自动监听，再按 `b` 启用只观察模式；屏幕应显示自动监听与插话观察，播报中确认后继续播放。`b` 单独不启用空闲自动监听，`r` 会关闭观察，本次也先不按实际打断开关 `i`。按 `?` 可在任意时刻取前端快照。固定扬声器音量、设备与麦克风摆位，并关闭风扇：
