## 操作与开关

| 串口键 | 含义 |
| --- | --- |
| `i` | 开启／关闭自动插话；开启时同时启用空闲自动监听，开机关闭，需要独立 D2 固件、连接及 AEC 就绪 |
| `a` | 回到半双工自动监听，关闭 D2 和 D1 观察；播报期间不自动打断 |
| `b` | 切换 D1 观察，关闭实际自动打断；确认后继续播报 |
| `r/s` | 手动原始 PCM 录音／结束；`r` 关闭插话和自动监听 |
| `c/m/n` | 取消／回到手动／重连，关闭插话；`c` 同时停止自动监听 |
| `?` | 保存本地前端、插话、音频参考和资源快照 |

只需在会话就绪后按 `i`，不必先按 `a`、`b`。待屏幕显示自动监听并安静片刻后提问。助手播放时显示“播报中，可插话”；此时说一句完整短句，确认后会实际停止当前播报并处理新问题。默认编译开关 `VOICE_BARGE_IN_ENABLED=n`；依赖 D1、AEC 及自动监听，现有默认固件和独立 AEC／D1 固件保留。

已有 D1 曾把回声判成持续人声，显式开启 `i` 后仍可能造成误停播；本批没有靠调整确认阈值、音量、模型或网络预算来掩盖该现象。需要恢复当前半双工体验时按 `a`。

## 实现与失败边界

AFE 回调只接收连续 20 ms PCM、记录 VAD 并维护固定 PSRAM 缓存，不在回调中停播、发送取消、创建新回合或等待控制器状态锁。确认采用当前 200 ms 连续人声窗。控制任务按下面顺序执行：

1. 在同一采集锁下，将 400 ms 预录、确认期及期间新增的连续 AEC 输出交给自动发言缓存；逐帧保留人声标记，短句若已经满足 700 ms 尾部静音，仍保留完整这一句并进入排空状态。
2. 核对旧回复身份和原子修订号，先封存旧 epoch／turn／generation，再执行本地停播栅栏。旧文字、音频、播完事件不能恢复已封存的回复。
3. 停播返回后发送 `response.cancel`，等待完整匹配旧身份的 `response.cancelled`。重复、旧回合、其他 generation 的确认不启动新轮。取消发送前已建立等待状态，因此立即返回的 ACK 也不会丢失。
4. 匹配 ACK 后，控制任务只创建一次新回合，经 `speech.start`／`speech.started` 和 `audio.stream.start` 启动上行。确认至音频流启动共用原有 2 秒预算，ACK 不会刷新该预算；上行 worker 在发送流启动和启用采集前都重新检查期限。重复 `speech.started` 不重复排入流启动。
5. 讲话缓存及后续连续输出沿原有 20 ms 节奏上行，不突发灌入服务端。保留 700 ms 静音结束和 30 秒上限；新回合结束后仍先观察 300 ms 静音再恢复自动起轮。

确认后即便尚未拿到取消 ACK，连续讲话也进入自动缓存，不依赖扬声器仍在播放。交接使用最后 AFE 输出边界，避免用领先的原始采集时钟丢弃讲话开头。取消前已说完的短句也能在握手完成后排空，无需再说一遍。

超时、参考／AEC 失效、连续样本断裂、缓存溢出和活动前端 500 ms 停滞会终止交接。未确认旧回复已经取消时不开新轮；失败锁存后控制任务清空缓存并关闭会话，`n` 显式重连，不重放本次 PCM。用户主动按 `a/b/c/r/m` 可丢弃尚未开始的新句缓存，但取消屏障保留到 ACK 或超时；`r` 的全新手动录音在屏障解除后才开始。

每帧新增人声标记，布局为 656 bytes。当前 D2 自动缓存与候选缓存各为 134 帧、87,904 bytes，共 175,808 bytes PSRAM。没有新增任务、模型、分区或对话音频落盘。底层音频驱动、参考时线、AEC 调度与前一稳定版本一致。D1 保留原观察行为，当前每帧布局变化与历史 648 bytes 记录分开说明。

## 服务端和时序记录

服务端 `response.cancelled` 在旧 LLM／TTS／音频任务清理完成后发送，可以作为新轮屏障。初版 D2 仅新增协议测试；上一批修改 TTS 取消／关闭抢占及流水线取消顺序，补充 `voice_response_cancel` 分阶段日志，见[取消清理修复](p43d2_cancel_timeout_fix.md)。本批再限制下行音频发送节奏，增加设备 `cancel_ack_transport` 接收／入队／分发日志及控制器 `cancel_ack_dispatch` 身份匹配诊断，见[本批修复](p43d2_downlink_ack_fix.md)。需要重启服务并烧录新 D2；设备仍按 2 秒总预算关闭未确认会话，完整云链路并非硬实时保证。

新增 `barge_in_handoff` 日志事件：`confirmed`、`local_fence`、`cancel_ack`、`speech_start`、`first_uplink`。携带本地 `at_us`、身份及必要采样边界，可比较确认、停播调用、取消确认和新首包时序。确认日志在本地停播之后输出，防止 UART 打印拖慢停播；`at_us` 保留实际确认时刻。`first_uplink` 表示新轮首个音频发送调用成功，日志由控制任务在发送路径之外输出。

停播函数耗时不等于实际声学停声延迟；健康 AEC 路径沿用有界静音排空及 SD 静音，已提交尾音、房间混响和主观停声仍需设备观察。此功能不修复此前服务端观察到的 1.36 秒媒体到达空档，也没有放宽 750 ms 上行保护。

## 烧录和本轮实机验收

关闭占用 COM7 的旧监视器，在 ESP-IDF 终端分两行运行：

```powershell
cd C:\esp-project\voice_assistant
idf.py -B build/barge-in-d2 -p COM7 -b 115200 flash monitor
```

使用 `build/barge-in-d2`，当前 `build/barge-in-test` 仍是 D1 观察固件。烧录后等待连接就绪，按 `i`。本轮直接验证 D2，不追加要求先重做 D1 对照或此前跳过的 B 专项：

1. 正常提问并等助手出声，播报中说“停一下，告诉我现在几点”等完整短句。应停止旧播报，并识别、回答新问题；留意开头和末尾是否完整。
2. 在另一轮播报中说较短的一句后停止讲话。即使取消握手尚未结束，也应处理已经说出的这一句，旧回复声音和文字不应恢复。
3. 连续插话几轮，再按 `a`。半双工模式下播报应继续，期间讲话不再自动停播。`r/s` 和 `c` 保留可用。

提供结果和 `?` 快照即可。若助手自己播报导致自动停播，记录为既有误确认在 D2 下的实际影响；可按 `a` 回退。无需更换接线、申请密钥或修改云端模型。
