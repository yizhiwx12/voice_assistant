## 最新设备证据

两份日志均运行 ELF `e1c95204c`，`feed_core=1 fetch_core=1`；实际预填 4164 样本，目标 3840，分别等待 253320/159605us，`deadline_hit=0`。用户确认播报卡顿改善。

| 附件 | 播报期间故障 | 候选与确认 |
| --- | --- | --- |
| 9b042373 | 36.859s IDLE0 WDT，现场 voice_rx/Opus decode；36.931s reference_gap；麦克风 clock_jump=52468us | 1 个候选，200ms 窗口 AC RMS=52<80，被能量门限拒绝；确认 0 |
| d139d898 | 30.298s、35.623s IDLE0 WDT，现场 voice_ws/tcpip；35.673s reference_gap；麦克风 clock_jump=50590us | 故障前候选 0，确认 0 |

两次都没有新的 pair_age；故障时前端队列为 0，frontend_waits=0，capture overflow=0。首答 binding_fault=0，旧启动静音丢块计数未新增。AEC 停用后，观察模式明确显示 `phase=fault reason=aec_unavailable`。用户在播报中后段以正常识别音量说话；该阶段可能已无可用检测链路，不能直接归因于声学灵敏度。

服务端 epoch=4049390936/turn=1 的 45440 样本是初次录音的 2.84 秒：识别 8 字、无削波、lag=103ms。D1 的播报期音频不上传，这段 ASR 指标不能衡量插话效果。当前仍为 `mode=observe upload=0 interrupt=0`，根 sdkconfig 没有编入 D2 停播功能。

## 调度修改

旧播放和分发各自 `vTaskDelay(1)`，当前 tick 为 1000Hz，二者可能轮流就绪，使 IDLE0 始终得不到执行；个别任务阻塞过不等于 CPU 有空闲。新 `main/app/audio_idle_guard.{hpp,cpp}` 注册常驻 CPU0 idle hook，两 worker 在完整帧/回调结束、没有音频锁和借用缓冲区的边界检查同一个实际 idle 进度：连续 50ms 没有 idle 时，以最多两 tick 为单位让行，看到真实 idle 或达到有限上限后继续。

- 播放/reference 每次请求等待最多 8ms，之后继续参考服务。
- 分发每次请求等待最多 100ms，给播放跨越帧边界的机会；停止标志在切片之间检查。
- 保留原有优先级、各 worker 工作预算、FIFO、160ms 启动预填、200ms 配对年龄和时钟健康保护。
- idle hook 只读取 tick、记录两个原子量，不打印、不分配、不取应用锁；所有 guard 状态显式在内部 DRAM。初始化注册失败明确返回错误。
- 新增 CMake 源文件；没有编辑第三方 managed components。

ESP-IDF 的 task_wdt.c 会在 watchdog ISR 内同步打印任务和回溯；麦克风使用 DMA ISR 到达时间。因此 WDT 打印延迟时间戳是当前强嫌疑，日志尚不能证明准确丢失/延迟了几个 DMA 事件。解决 idle 饥饿是修复目标，不能以放宽 50ms 时钟门限或关闭 WDT 掩盖。

`?` 打印 `audio_idle`：initialized、generation、gap_ticks、observed_max_gap_ticks、waits、wait_ticks、max_wait_ticks、timeouts、cancelled、tick_hz。计数是启动以来两个 worker 合计，max gap 是检查点观测最大值。请求等待上限不限制被其它高优先级任务抢占的墙钟时间；SDK/Wi-Fi 持续就绪仍可能导致超时/WDT。100ms 分发让行也可能增加包括 cancel ACK 在内的控制延迟，8ms 播放让行会消耗参考时间余量，均需设备验证。

## 无候选时的 VAD 证据

启动读取真实 SDK `get_vad_energy_threshold` 和 `get_vadnet_threshold`；成功 fetch 记录 `data_volume`（SDK 定义的 128ms VAD 输入窗 dBFS）。`vad_input` 指标提供当前值、启动期峰值、有效/无效窗数；`INT32_MIN` 表示不可用，单位 cdbfs=0.01dBFS，-6000 即 -60dBFS。

新增每回复 `barge_in_signal`：即使没有候选也保留输出帧数、speech 帧数、实际输出帧 AC 峰值、异步麦克风快照峰值、去重后的 VAD 输入窗峰值和高于 SDK 能量门限的窗数。只在显式 `?` 打印；新回复重新统计，故障后保留已有证据。异步 mic/output 不做样本对齐，不用这些峰值比值计算 AEC 衰减。

小智 2.5.2 当前依赖 ESP-SR 2.4.7，本项目为 2.6.1；后者 2.5.0 起新增 VADNet 最低能量门限。本项目实际日志为 -60dBFS，单个 output RMS 不能替代该 128ms 窗。小智通用 NoAudioCodec 的 I2S 位移还比本项目 gain=1 高约 24dB，但硬件、削波余量不同，不能直接照搬增益。本轮不改 VAD、NLP、gain、AC80 或 D1/D2 判定。
