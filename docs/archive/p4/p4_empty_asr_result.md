## 本次修改

1. 空识别使用现有Complete结果页显示提示；不再映射为Ready。保留VAD页脚、下一轮`r`重试，并忽略已取消回合的迟到空结果。
2. 豆包适配器新增固定数值`recognition_metrics()`：成功解析的正常响应数、非空完整文本响应数、成功发布的partial/segment事件数、是否收到最终结果和最终字符数。响应数包含握手，重复文本响应仍计数，片段事件仍去重；不改变请求、解析和超时语义。
3. 服务端每轮新增`voice_asr_result`，记录实际成功写给设备的识别事件数量、最终结果分类和字符数。结果分类为`text`、`empty`、`failed`、`canceled`或`no_final`；空最终、异常和取消分别记录，不把超时变成空识别。
4. 对实际成功交给ASR的解码后PCM做常量空间音量统计，包含Opus lookahead和结束边界裁剪后的尾部；每轮清零，不保存音频、不输出对话内容。

新增日志的关键字段：

| 字段 | 含义 |
| --- | --- |
| `outcome` / `final_chars` | pipeline最终结果及写给设备的最终文字长度 |
| `provider_responses` / `provider_nonempty` | 豆包正常响应数（包含握手）及含非空完整文本的响应数 |
| `provider_final` / `provider_final_chars` | 是否收到真正最终响应及最终文字长度；适用于豆包 |
| `device_partials` / `device_segments` / `device_finals` | 成功完成WebSocket写入的识别事件数，不等于设备已渲染确认 |
| `pcm_samples` | 本轮实际成功交给ASR的PCM样本数 |
| `pcm_rms` / `pcm_ac_rms` | 整轮总RMS及去直流RMS；两者差异很大时需排查直流偏置 |
| `pcm_peak` / `pcm_clipped` | 最大绝对样本与达到PCM16上下限的样本数 |
| `pcm_frame_rms_max` | 各次feed块的最大RMS，帮助避免长静音掩盖短讲话；块可能含裁剪尾部 |

音量数字不等于可辨识度或信噪比。`outcome=empty provider_final=1 final_chars=0`表示云端最终结果为空；`provider_nonempty>0`但最后为空时，还需检查云端文本修订。`device_finals=1`仅证明服务端写入成功。无最终/超时保留失败分类。
