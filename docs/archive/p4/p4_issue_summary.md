当前实际音频路径：

```text
ICS-43434 → PCM16/16kHz（gain=1）
              ├─ 手动 r/s → Opus → 服务端解码 → 所选云ASR → LLM → TTS → 播放
              └─ ESP-SR AFE/VADNet →
                    ├─ 未按a：独立人声／静音观测
                    └─ a自动模式 → 400ms目标预录/有界握手缓存 → Opus → 服务端ASR
```

`r/s`仍上传原始PCM作为手动基线；`a`显式启用AFE输出的半双工自动路径，`m`退出。自动端点由VADNet讲话候选和700ms静音共同控制，当前目标预录为400ms；下方200ms场景和时长分析属于P4.2历史。服务端仍负责整轮final并仅提交一次，助手播放期间暂停自动起轮。默认构建为单麦`M`、AEC关闭；独立`build/aec-test/`显式启用`MR`／SR_LOW_COST AEC，本轮实机采用此配置。NS、AGC、WakeNet仍关闭，MultiNet未接入，自动插话未实现。

4. **归档基础稳定结果，保留AEC声学待办**：第八批`17284ff146`已由用户运行，最新日志确认身份、四轮上行结束和健康／资源样本，用户反馈“一切正常”；见[AEC问题复盘](p43c_aec_issue_retrospective.md)与`build/p43c_eighth_repair_hardware_observation.json`。本轮仅归档，不要求追加验证；后续保留受控远端／近端／双讲、刚停播、完整取消／长播专项及声学校准待办，D仍关闭，不重做已跳过的B。
5. **最后启用自动插话**：AEC验证通过后，确认人声再停止旧播放／取消旧回复、封禁迟到包并启动新发言；首字、取消重连和资源专项随批次回归。详细交付和用户实测项见[P4.3执行方案](p43_aec_execution_plan.md)。
